# 编剧 swarm

用户调用本命令，即委托你选择适用技能并分派。最终交付编剧此刻可以采用的选项：选题给故事切口，大纲给结构走法，分场给下一拍，审稿给定位和改法。沿用上文已定的人物、版本、受众与硬限制。命令没有参数时，接着最近一项未解决的创作决定做；连上文也没有创作对象时，只问「把正在写的那段或正在犹豫的决定发我就行」。

## 发现与分派

1. 用一句话写出本轮要帮作者做的决定。先扫描整个项目技能目录：从采集项目根运行 `python3 剧本系统/tools/skill_catalog.py`，其他工作目录可用本文件旁 `catalog.py` 的绝对路径。分段读完输出，包含嵌套技能；不依赖已注册斜杠命令或静态白名单。
2. 对目录逐项判断「它能用什么具体方法或素材给这个决定提供另一种走法」。从故事模型、剧集案例、套路与梗、人物/对白、导演审读与视听、热点与题材等方向检查遗漏。阶段用于明确产物，允许跨类：问结尾时，结构模型可以重设最后的决定，剧集可以借回收机制，导演视角可以让那个决定变成看得见的动作。多种理解都有依据时并行试。只有会改变答案的技能入选；名字相近时读正文再决定。此命令是显式委托选用，允许派具体技法做它擅长的练习；遵守资料、题材、时效和工具条件。排除调度器自身或会递归启动其他调度的入口，直接分派底层资源。
3. 用 Agent 工具**同批启动多个独立的本地 worker**。按探索方向分组，把每个入选技能分配到一个明确的组；同类技能可共用 worker，每个分配项均要实际读取、尝试。数量大时分批覆盖。每个 brief 自包含：原稿或路径与范围、同一创作决定、硬限制、本组各 SKILL.md 的完整路径、要求交回的具体结果。不要让编剧先选方法。worker 各自读技能正文及所需案例、运行技能所需查询，默认只回报；生成候选不改写原稿。没有并行工具时逐组执行并披露。
4. 每组回传「用过哪些技能 → 哪个动作或决定因此不同 → 会带来什么后果」，附一段能直接比较的试写、结构或审稿意见。案例组给剧集和证据；导演组写基于资料的视角；时事组给可核日期与来源；新编情节标为改编或原创。没有合适结果也回报技能及原因，不能把未跑的组记成查无结果。

## 交给编剧

等各组返回，再核对每个分配项是否有结果。合并不同方法得出的同一解，保留会让人物选择、观众所得信息或结局代价真正不同的走法。缺省先展开最有区别的三条，其余独立可能每条一句，用户要看全部时逐条展开。每条交代怎么写、适合保住什么、会牺牲什么，列实际贡献来源。导演或模型有冲突时指出作者究竟要选哪个创作效果。末尾简列尝试范围、无命中与缺口。用户选中一条后沿用它往下写。
