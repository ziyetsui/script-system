# 剧本爽点缺失校验 — 用总目录体检你的剧本

## R — 原文 (Reading)

> 爽感来源：对比、反差、信息差，适用于都市、玄幻、历史各类题材，可以迁移改编。
> 风险提醒：无脑装 X、强行降智容易引起读者反感；爽点不只局限打架打脸，
> 物质收获、地位提升、他人崇拜、感情收获，同样是有效爽点。
>
> — 《400 个爆款短剧剧本爽点》，四、通用创作要点

## I — 方法论骨架 (Interpretation)

本技能包把短剧/网文爽点体系化为四大类（A 身份反差・隐藏大佬 8 个、B 实力碾压・越级反杀 7 个、C 打脸反转・当众处刑 6 个、D 特殊叙事手法 4 个），共 25 个爽点套路 + 1 个底层引擎（信息差）。**校验**就是把一部剧本逐场景与这份清单对照，回答三个问题：

1. **爽点分布是否失衡**？——是否只集中在某一类（如全是打脸），缺其他类别？
2. **爽点密度是否合理**？——是否该有的地方没有（该爽的集数平了），或过于密集（集集无脑震惊）？
3. **是否踩了雷**？——无脑装 X、强行降智、单维爽点（只会打架打脸）？

校验的输出是一份"体检报告"：按场景列出爽点命中情况、缺失维度、雷区警示，并给出改进建议（指向对应的子 skill）。它把本技能包从"素材库"升级为"质检工具"——生成桥段用子 skill，检查剧本用本 skill。

关键手法：**按"集/章/场景"逐段打标**（该场景命中了哪个爽点类别），**按"多维爽点原则"查漏**（打架打脸之外，物质、地位、崇拜、感情四维是否覆盖），**按"反降智原则"排雷**（配角行为是否合理、主角碾压是否有代价）。

## A1 — 书中的应用 (Past Application)

### 案例 1: 连续打脸集数的体检
- **问题**: 剧本前 10 集全是"嚣张转谄媚"，观众会不会疲劳？
- **方法论的使用**: 逐集打标发现 C 类命中率 100%、A/B/D 类为 0，且全是打架打脸（单维）。
- **结论**: 爽点分布失衡 + 维度单一，需补充身份反差、资源碾压、感情收获等维度。
- **结果**: 建议第 5 集插入隐藏身份揭晓（a03/a01），第 8 集插入施恩遇贵人（a08）切换维度。

### 案例 2: 降智雷区排查
- **问题**: 反派已经见识主角实力，为什么还在无脑挑衅？
- **方法论的使用**: 用"反降智原则"逐场检查配角行为的信息量与立场。
- **结论**: 反派行为无法由其信息量解释（强行降智）。
- **结果**: 建议改写反派动机（他不知道/被利用/有更大靠山），并补充信息差结构（d03）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 完成剧本初稿，需要"爽点体检"（哪里不够爽、哪里踩雷）。
2. 编辑/作者投稿前自检（爽点密度与多样性）。
3. 创作中途卡壳：不知道下一集该上什么爽点（用清单查漏）。
4. 短剧投放前评估（短剧单集 3 分钟内必须有爽点爆点）。

## E — 可执行步骤 (Execution)

1. **分集/分场景打标**
   - 完成标准: 把剧本按集/章/场景切分，逐个标注命中的爽点类别（A/B/C/D + 具体 skill 编号）；无爽点命中的场景标记为"平"。
2. **统计分布与密度**
   - 完成标准: 输出统计表：各类别命中数/占比、连续"平"的段落（该爽没爽的地方）、连续同类命中的段落（可能疲劳）。
3. **多维爽点查漏**
   - 完成标准: 对照"打架打脸/物质收获/地位提升/他人崇拜/感情收获"五维，标注剧本覆盖了哪些维度、缺了哪些维度（源文档明确：多维才是有效爽点）。
   - 判停条件: 若剧本是短剧（单集 3 分钟内需爆点），检查每集是否至少 1 个强爽点；不满足则标记该集需补强。
4. **雷区排查（反降智/反无脑装 X）**
   - 完成标准: 逐场检查：配角行为能否由其立场/信息量解释（降智排查）；主角碾压是否有铺垫与代价（装 X 排查）；反差异常是否无梯度（疲劳排查）。
5. **输出体检报告**
   - 完成标准: 报告包含：① 爽点分布表；② 缺失清单（某类 0 命中、某维度缺失、某集太平）；③ 雷区清单（具体场景 + 问题）；④ 改进建议（每条指向对应子 skill，如"第 X 集补 a02 微服被刁难"）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 用户要的是"生成桥段"而非"评估剧本"——生成请用对应子 skill。
- 非爽文向严肃叙事（文艺片、正剧）——爽点清单不适用。
- 用户未提供剧本文本——需要先拿到剧本才能校验（不凭印象评估）。

### 作者在书中警告的失败模式

- **机械执行**: 只统计数量不判断质量——爽点不是越多越好，密度过高（集集无脑震惊）同样是雷；校验必须同时看"分布"与"梯度"。
- **公式化建议**: 把缺失清单当补丁列表直接塞入剧本——桥段必须服务人物与因果链，否则就是 ce05"套路流水线"（照搬清单只产出工业糖精）。

### 作者的盲点 / 时代局限

- 校验标准基于短剧/免费网文的快节奏审美；若剧本是长剧/精品网文，爽点密度标准应相应放宽（避免每集强行爆点）。

### 容易混淆的邻近方法论

- 与"生成类子 skill"的边界：本 skill 只评估、不生产；评估中发现缺什么，才调用对应子 skill 去生产。
