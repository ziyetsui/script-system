# 找梗

把用户的卡点交给相关的剧集梗库和技法技能，给编剧几种可以直接往下写的动作。用户说「缺梗」但没给戏时，只问一句「谁想做什么，写到哪一步卡住了？」已有上文就沿用。

## 找全相关技能

1. 用一句话提取当前人物、目标、阻力和用户要保留的限制。判断缺的是开局、升级、并线、反转、收尾，还是其他具体动作。用户指定类型、剧集或排除项时以其范围为准。
2. 从项目采集根目录执行 `python3 剧本系统/tools/skill_catalog.py`。读完输出的路径及用途，包括二级以下的专题技能。每次重新发现，新增目录自然加入。用户说「所有相关」时，在全目录中按下列条件逐项筛选，别只搜字面关键词。
3. **剧集梗库**：凡能给当前戏提供故事机制的素材库都纳入；没有题材限定的家庭情景喜剧卡点，默认把所有家庭情景喜剧梗库纳入。**专题技法**：描述中有能改变当前人物下一步选择的具体办法就纳入，例如瞒骗、三次递进、误判、道具回收。打开边界含糊项的 SKILL.md 核对适用条件；遵守技能明确的点名限定。导演审稿、画图、制作工具、热点搜集等只在用户同时要求对应产物时纳入。不要选本入口自身或再次启动同类调度器。

## 并行找，再合并

4. 同批启动本地 `general-purpose` subagent。各剧库分开派；针对同一机制选中的多个技法可交同一 worker，给出每个文件的完整路径。技能数多时分组或分批，保留所有相关项。每份任务都带同一份原稿片段、限制、所分配技能和交付格式。要求 worker 读取每个 SKILL.md 及必要参考，独立找梗，只返回结果。每项给一个符合限制的候选，或说明为什么没有合适命中。专题 worker 不重复检索其他组的库。运行环境无法启动 worker 时逐组读取并说明执行方式。
5. 梗库候选带集号、原卡名、原稿短引和可迁移机制；方法类标明技法来源与本次原创桥段。每条写清「谁先做什么 → 谁因此换招 → 新局面」。核对出处和用户限制。工具不可用或证据不足的项说明缺口，不编造原剧场面。
6. 默认给最适合的三种不同因果，用户指定数量时照办。先写能直接接进用户稿子的下一拍，再附机制、出处和适用前提。按**行动与后果**合并重复建议，合并时保留各来源。末尾用一行报实际调用了哪些库和技法，以及未返回的组。用户挑中一条后直接展开那条。

例如用户说「孩子把奖状藏起来了，妈妈来敲门，我不想再写有人打电话救场」，各组都必须保留这个禁用条件。给编剧的选项应落实到孩子现在做什么、妈妈因此误判什么，以及这个动作给下一场留下什么麻烦。
