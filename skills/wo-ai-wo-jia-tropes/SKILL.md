# 《我爱我家》梗库

## 编剧说「这场卡住了」

1. 从用户的戏里摘出谁想做什么、哪个动作写不下去、想让谁付代价。把卡点改写成能搜索的短词。例如「爸妈先许愿，孩子当真做到了，接下来怎么接」可搜 `好成绩 奖励`；用户给了剧本就直接从稿中取词。
2. 在项目采集根目录（同时含 `剧本系统/` 和 `docs/`）运行下方命令。每行是一张预先做好的卡。关键词匹配梗名、卡点、公式、原集因果和集标；命中多词的卡排在前面。读候选卡的 `beat` 和 `formula`，检查推动情节的是不是同一个动作。命中太少就把人物名换成关系、把主题换成动作或后果，例如把「亲子教育」换成「奖励」「劝退」「兑现」。

   ```sh
   python3 剧本系统/skills/trope-library/trope-library.py wo-ai-wo-jia 好成绩 奖励 --limit 8
   ```

3. 按用户所需数量挑卡。有多解时选因果不同的写法，指出各需要什么前提。每条写出**梗名、原集动作及后果、如何接到用户这场**。署集号、集名、`beat` 所记时间和 `anchor` 短引。替换人物、道具和代价，保留使下一步不得不发生的条件；新写情节标作改编。用户选中某张，沿用它继续写，无须让用户重讲设定。

## 用户点集或跨集找梗

- **「列出第 3 集所有梗」**：先取出本集全部入库卡。给足 `--limit`，只保留 `episode` 符合的行；同名上下集以三位集号区别。报已收录条数，按故事发生顺序排列，每条附触发、回收与迁移公式。

  ```sh
  python3 剧本系统/skills/trope-library/trope-library.py wo-ai-wo-jia '「003」' --limit 1000
  ```

- **「哪些集有类似机制」**：用动作和后果分次搜索，按「谁先知道」「谁承担代价」「什么动作引出反转」比较，去掉一条因果链的不同叫法。用户要求跨全库查全时遍历 [cards.jsonl](cards.jsonl) 各集候选并核读；区分现有卡库覆盖和原片逐场补查。
- **「把这一集再拆全／查出处」**：从卡的 `source` 到 `docs/materials/videos/` 下取原稿，搜索 `anchor` 回到分段。要补全一集，按时间读完正文和最后一次情节回收，排除片尾重拍、串场和其他集花絮。逐场记「谁想得到什么 → 做了什么 → 谁因此改了选择或处境」。回扫支线、道具的二次用途和第一次失败的尝试；能独立更换人物道具且保留因果的另列一条。同一机关反复出现、后果相同的合并写；只有伏笔的记为待回收。上下集各引各的本地时间，确需下集才能成立时同时列出两集证据。
- 资料是本地 SenseVoice 音轨分段转写。时间指该版音轨的分段，姓名、同音词、说话人和断句可能有误，不能仅凭空白段推定动作、镜头或人物内心。保留能逐字搜回的短引，剧情用自己的话转述。原文不能确认的环节标「待核」。
